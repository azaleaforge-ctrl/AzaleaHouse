# Document Engine — Initial Local Authoring Slice

**Development version:** 0.1.3 (source/configuration metadata only)  
**Scope:** First usable implementation of PRD Phase 6. This is not a claim that the full document engine is complete.

## What this increment delivers

- Replaces the Documents placeholder with an editor and live A4-oriented preview.
- Markdown content maps to headings, paragraphs, unordered/ordered lists, tables, inline bold/italic/code and explicit PAGEBREAK page breaks.
- Creates an editable OOXML DOCX locally under .AzaleaMemory/documents/ without spawning a document executable or sending content to a remote service.
- Uses Office Open XML styles for document title and heading hierarchy, list numbering, table borders/header shading, A4 page size, one-inch margins, metadata, and a footer with a page-number field.
- The generated DOCX is built from a Store-compressed ZIP package; all text is escaped as XML and file paths are generated by the application, not accepted from the UI.
- PDF uses the Windows print dialog. Users choose Microsoft Print to PDF and select a destination in that dialog.

## Limits intentionally left visible

- This is a deterministic formatter, not yet an AI-to-document workflow. Users can draft in Chat or elsewhere and paste Markdown into the editor.
- Direct PDF byte generation and automated PDF render validation are not included. The app does not claim that a PDF was saved when it has only opened the print dialog.
- DOCX openability/layout still needs manual acceptance in Microsoft Word or a compatible office suite. Pagination may differ from the browser preview.
- Table-of-contents fields, cover pages, headers, footer customization, page-size/margin controls, images, and full Markdown compatibility are not in this slice.

## CI and manual acceptance

GitHub Actions for the current PR should pass:
- npm ci
- npm run build
- cargo check --manifest-path src-tauri/Cargo.toml --all-targets
- cargo test --manifest-path src-tauri/Cargo.toml

Manual acceptance after building the Windows app:
1. Create a title and paragraphs and save DOCX; confirm the file opens in Word/LibreOffice without repair warnings.
2. Check heading hierarchy, bold/italic/code, numbered/bulleted lists, and a table.
3. Check accented and Indonesian characters, punctuation, ampersands and angle brackets.
4. Include [[PAGEBREAK]]; verify page break in Word and PDF print workflow.
5. Use Print / Save PDF and confirm Microsoft Print to PDF produces an actual PDF with correct margins and no UI chrome.
6. Confirm files are inside the configured .AzaleaMemory/documents/ folder and Buka folder opens that directory.
7. Try blank content, blank title, oversized content and repeated same title; confirm errors or unique filenames rather than an overwritten file.
